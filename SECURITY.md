# SSRF security checklist

Link Check outbound probes are guarded in `link_check_server/lib/src/link_check/`. Rows are backed by automated tests in `link_check_server/test/unit/`; the status column says exactly what each test run does and does not cover. All unit tests run offline (fake DNS, sockets and HTTP client).

| # | Control | Status | Proof test(s) |
|---|---------|--------|---------------|
| 1 | **http/https schemes allowed** — reject `file:`, `gopher:`, `ftp:`, `data:`, `javascript:`, and `user:pass@` | **PASS** | `link_check_security_test.dart` — groups “scheme and credentials (SSRF #1)”, “ports and limits (SSRF #6)” → “uses the reworded, UI-safe validation messages” |
| 2 | **Block private/loopback/link-local/metadata IPs** — 127/8, ::1, 10/8, 172.16/12, 192.168/16, 169.254/16, fe80::/10, fc00::/7, 100.64/10, 0/8, ::ffff: mapped | **PASS** (address literals) | `link_check_security_test.dart` — group “blocked networks (SSRF #2)”: “blocks every range listed in SECURITY.md row 2 (edges included)”, “does not block public neighbours just outside blocked ranges”, “rejects blocked IP literals in URLs, including IPv6”. Not blocked by design: deprecated site-local `fec0::/10`. |
| 3 | **Normalize encoded hosts** — decimal/octal/hex IPv4, trailing dot, punycode (`xn--`) | **PASS** | `link_check_security_test.dart` — group “host normalization (SSRF #3)” |
| 4 | **DNS rebinding** — each hop resolves the host once for the connection and TCP-connects to that checked IP via `HttpClient.connectionFactory` | **PASS** (fake resolver and fake socket; no live network) | `link_check_security_test.dart` — “DNS pinning (SSRF #4)” (first public answer wins, all-blocked and empty answers rejected); `link_check_service_test.dart` — “connects to the checked public IP, not to a blocked sibling”, “a host that rebinds to a private IP before connect is rejected, no socket opened”, “a redirect hop is resolved again and pinned to its own checked IP”. **Not covered:** the real `dart:io` client with real DNS/TLS sockets. `check()` also does one extra pre-check lookup before hop 1; the connected IP is always the one resolved and checked for that hop. |
| 5 | **Redirects manual, max 5, re-check 1–4 on every hop** | **PASS** (fake HTTP client; no live network) | `link_check_service_test.dart` — group “redirects re-checked on every hop (SSRF #5)”: private IP, metadata IP, hostname resolving to a private IP, bad port/scheme, relative redirects, exactly 5 hops succeed, 6th redirect gives “Too many redirects.”, `followRedirects` is false. **Not covered:** a real server returning real redirects. |
| 6 | **Ports 80 and 443 allowed, 3s connect, 10s total, 1 MB body max, GET/HEAD** | **PASS** (config values and port rule) | `link_check_security_test.dart` — “ports and limits (SSRF #6)”. **Not covered:** the 3s/10s/1 MB limits are asserted as config values only, not exercised against a slow or oversized response. |
| 7 | **No cookies/auth headers out, no raw body or internal IPs in errors, rate limit per client** | **Implemented, partly tested** | Tested: `link_check_service_test.dart` — group “headers and error text (SSRF #7)” (`User-Agent` is the sole header set; connection, TLS and HTTP failures and internal-target validation errors never contain IPs, cookies or upstream text); `link_check_security_test.dart` — “LinkCheckRateLimiter (SSRF #7)” (limiter logic). **Not covered:** the endpoint's per-client key (`session.request.remoteInfo`) and its “Rate limit exceeded” response; the generated test tools create a new session per call, so a repeat-caller test is not possible there. |

Maintainers: after changing validation or fetch logic, run `cd link_check_server && dart test` and update this table if a row’s proof tests move.
